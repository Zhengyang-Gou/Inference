# 仿真机制覆盖与扩展范围

本仓库研究 profile 驱动的计算事件、容量约束和 ns-3 分组网络事件。下面列出已建模机制及可独立扩展的仿真维度。

| 机制 | 当前模型与扩展范围 |
| --- | --- |
| Decode 连续批处理 | 每轮每成员返回 1 token，共享批次计算与通信；按最大上下文 padding 估算，可扩展为异长序列代价模型 |
| Chunked / packed Prefill | 支持 token 分块、块边界轮转、running 优先和 FCFS 合批；多请求 attention 采用独立代价之和 |
| 分页 KV | 当前按对象字节管理容量并按整请求预留；页表、碎片和逐页增长可作为独立仿真机制加入 |
| 抢占、重计算与 offload | 当前通过 admission 等待容量；扩展时需显式建模暂停、数据迁移和重计算成本 |
| 计算成本 | 使用离线公开算子数据或合成代价曲线；融合、串行附加开销、计算倍率通过显式参数研究 |
| 集合通信 | TP ring、EP dispatch/combine 与 KV 共用网络模型；节点内为共享 FIFO，可进一步扩展通信算法和局部互联模型 |
| 权重与 KV 表示 | MoE 主线使用 FP8 权重和 BF16 MLA KV 假设；不同表示需分别声明容量、计算和通信成本 |
| Speculative decoding | 当前没有草稿、接受率、回滚过程；每个 D 成员每轮返回 1 token |
| 资源与并行 | P/D、TP 和 EP 由配置固定；暂未建模运行时弹性与 PP |

后续优先通过计算代价、带宽、显存容量和组批参数的敏感性实验评估结论稳定性。新增机制需要守恒检查及端到端仿真对照，不能直接引入未声明的固定加速倍数。
